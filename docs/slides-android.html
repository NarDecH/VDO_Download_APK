การตรวจจับ

Detector.kt — ตัวตรวจจับ 4 ชั้น ฉีดในทุกหน้า

1 · DOM scan

<video>, <source>, <audio>, meta og:video, JSON-LD และลิงก์สื่อทุกชนิด

2 · Hook fetch/XHR

ดัก request m3u8 / mpd / mp4 ที่ JS เรียกเอง (รันใน MAIN world จึงเห็นของจริง)

3 · Resource timing

เก็บ URL จาก performance entries ที่หลุดจากสองชั้นแรก

4 · Iframe scan

frame same-origin สแกนลึก · cross-origin player รายงานเป็น embed เพื่อชวน "เปิดหน้า embed"

  • รู้จักนามสกุลสื่อกว้าง: mp4 · m3u8 · mpd · webm · mkv · ts · mp3 · m4a … รวม blob:
  • ทุกผลลัพธ์ dedupe ด้วย URL แล้วส่งเป็น JSON เข้า Bridge → เพิ่มรายการ + event media_found
  • กติกา repo: Detector.INJECT_JS ต้อง maintain เป็นคู่กับ DETECT_JS ฝั่ง desktop เสมอ
  • ทดสอบหน้าเพจจริง: ปุ่ม/ชิป "🎬 พบวิดีโอ" อัปเดตทันทีเมื่อพบสื่อใหม่
การดาวน์โหลด

สองเส้นทาง — เลือกอัตโนมัติจากชนิด URL

ไฟล์ตรง (mp4 / webm / mp3 …)

Downloader.kt → platform DownloadManager

· แนบ cookie ของ WebView (CookieManager) ให้โหลดโดเมนที่ต้องล็อกอินได้

· แจ้งเตือนความคืบหน้าของระบบ · เขียนลง Downloads/VDOGrabber

สตรีม (m3u8 / mpd)

StreamDownloadService → เอนจิน yt-dlp + ffmpeg บนเครื่อง

· รวมชิ้นส่วน HLS/DASH เป็นไฟล์เดียวบนอุปกรณ์ (ไม่ต้องพึ่งเซิร์ฟเวอร์)

· ครอบทุกไซต์ที่ yt-dlp รองรับ — เพิ่มขอบเขตตาม upstream อัตโนมัติ

  • ตัวจัดเส้นทาง: Downloader.isStream() — สแกนนามสกุลจาก URL (pure function, JVM-tested)
  • ตั้งชื่อไฟล์ตาม title ของหน้าเว็บ (sanitize ตัวอักษรต้องห้ามของ Windows/Android แล้ว) + กันชื่อซ้ำ ชื่อ (2).mp4 — parity เดียวกับ desktop
  • เคส Android <10: publish ต้องใส่ MediaColumns.DATA ด้วย ไม่งั้นไฟล์ไม่โผล่ (แก้แล้วใน v1.1.7)
เอนจินบนอุปกรณ์

StreamDownloadService — yt-dlp วิ่งในเครื่องผู้ใช้

  • youtubedl-android (library + ffmpeg) v0.17.3 — พินเวอร์ชันเดียวกับที่ Seal ใช้ ตรวจ artifacts บน Maven Central แล้ว
  • ไบนารี python/ffmpeg ที่แพ็กมาถูก exec() จริง → jniLibs.useLegacyPackaging = true เพื่อ extract ลง nativeLibraryDir
  • Foreground service (dataSync): notification แสดง % + ปุ่ม ยกเลิก ได้ทันที (destroyProcessById)
  • เสร็จแล้ว publish เข้า MediaStore (Downloads/VDOGrabber) — แจ้งเตือนมีปุ่ม "เปิดไฟล์" แตะดูได้เลยผ่าน content URI
  • ลบจากแจ้งเตือนได้ด้วย ผ่าน DeleteFileActivity (trampoline) + Toast ยืนยัน
  • ทุกขั้น emit event ชื่อเดียวกับ desktop: download_start · download_done · download_deleted … (snake_case)

เหมือนกด yt-dlp ในเทอร์มินัล แต่ผู้ใช้แค่กดปุ่มเขียว — แอปจัดการ args, cookie, ชื่อไฟล์ และคิวให้ครบ

หลังดาวน์โหลด

DownloadCleaner — ลบไฟล์ที่ดาวน์โหลดแล้วได้จากในแอป

  • ส่วน "ไฟล์ที่ดาวน์โหลดแล้ว" ในชีต 🎬 รวม 3 แหล่ง แล้ว dedupe ตามชื่อ + เรียงตามแก้ไขล่าสุด:
    • งาน DownloadManager ที่สำเร็จ (ไฟล์ตรง)
    • รายการ MediaStore ที่ publish แล้ว (Android 10+)
    • ไฟล์จริงในโฟลเดอร์ Downloads/VDOGrabber (เช่น ของเอนจิน yt-dlp)
  • ไฟล์เดียวอาจมีหลาย identity (งาน DM + แถว MediaStore + ไฟล์ดิบ) — ลบทีละ identity จนสำเร็จ
  • ออกแบบให้ทดสอบได้: ตรรกะล้วนอยู่ใน object เดียว จุดแตะระบบมีแค่ systemList / systemDelete
  • ปุ่ม "ลบไฟล์" มี dialog ยืนยัน · ลบแล้วแถวหายจากชีตทันที + event download_deleted
การมองเห็น

FileLog — log สามไฟล์แบบเดียวกับแอป desktop

app.log

ข้อความทุกอย่าง หมุนเวียน 2 MB เก็บ 3 ไฟล์

downloads.log

การกระทำและผลของการดาวน์โหลดทุกงาน

events.jsonl

เหตุการณ์ structured 1 JSON/บรรทัด — วิเคราะห์ด้วย jq ได้

  • อยู่ที่ /data/data/com.vdograbber.app/files/logs/ — เปิดดูในเครื่องได้จาก LogsActivity หรือ Device Explorer
  • ชื่อ event เป็น snake_case ตรงกับ desktop ทุกตัว: app_start · page_loaded · media_found · download_start · download_done …
  • เริ่ม log ตั้งแต่ onCreate — ทุกเซสชันมีร่องรอย ช่วยไล่เคส "ดาวน์โหลดไม่ได้" จากผู้ใช้ได้จริง
คุณภาพ

ทดสอบสองชั้น: JVM ล้วน + E2E บน emulator จริง

Unit (JVM, เร็ว)

Downloader (ext/isStream/humanSize/ตั้งชื่อ+dedupe) · StreamArgs · MediaStore LRU · DownloadCleaner — รันทุก push

E2E: StreamEngineTest

ffmpeg ใน runner ปั่น HLS จริง → เสิร์ฟผ่าน loopback → อุปกรณ์ดาวน์โหลด + รวมไฟล์ด้วยเอนจินจริง

E2E: DownloadCleanerE2E

สร้างไฟล์ 3 เส้นทาง (MediaStore publish / ไฟล์ดิบ / งาน DownloadManager จริง) → ลบ → ยืนยันหายจากดิสก์

  • Emulator บน runner บางครั้ง ADB ไม่ตอบสนองตั้งแต่บูต → รันใหม่อัตโนมัติ 1 ครั้งด้วย emulator ใหม่ แล้วค่อย fail จริง (เจอจริงบน tag v1.1.6)
  • Hardening: -no-snapshot -camera-back none ฯลฯ + ปิด animation — ลดความแปรปรวนของ software rendering
  • E2E เป็น gate: ไม่ผ่าน = ไม่ได้ release (CI ตัดสินแทนมนุษย์)
CI / Release

ปั่น APK อัตโนมัติทั้งสาย: จาก tag ถึงหน้า release

push tag v*android.yml เริ่มทันที (ubuntu-24.04 ปักหมุดไว้ — ubuntu-latest จะย้ายไป Ubuntu 26)
➜
unit + E2EtestDebugUnitTest → HLS fixture จาก ffmpeg → emulator ×2 attempts
➜
ABI splitsarm64-v8a · armeabi-v7a · x86_64 · universal — ตั้งชื่อ + sha256
➜
attach releaseอัปโหลด APK ทุกตัว + รวม checksums.txt + กัน release ค้าง draft
  • ABI splits ลดขนาด ~1/3 — เพราะ native lib ของ yt-dlp + ffmpeg ใหญ่ ผู้ใช้โหลดเฉพาะสถาปัตยกรรมเครื่องตัวเอง
  • checksums.txt รวมทุกไฟล์บน release (รวม exe ฝั่ง desktop) — ตรวจสิ้นเชิงหลังโหลด
  • ทุก branch ได้ artifact ก่อนขึ้น tag — ทดลองติดตั้งก่อน release ได้เสมอ
